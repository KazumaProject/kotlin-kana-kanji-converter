# テスト設計

| 検証 | 方法 |
| --- | --- |
| 通常候補と順位 | `corpus.txt` で変更前後の CLI top-100 をバイト比較。統合テストで通常 API と詳細 API の top-1/10/100 を照合。 |
| 探索の性質 | 固定 seed のランダム小規模ラティス700個。独立した DFS で全経路を列挙し、制約を満たす表記ごとの最小コスト、順位のコスト順、Viterbi の費用を照合。負の辺、非対称 ID、EOS、安価な無効経路を含む。 |
| 日本語の最小対 | 「意外な」と「以外な」、複合入力、禁止の「な」、仮定の「なら」、形容動詞語幹3種。単語表記の不存在は全経路到達性で検査。 |
| 迂回・不成立 | 境界をまたぐ長い単語、短い複数ノード、左右で異なる解釈を用いた経路、安価な違反経路と高価な合法経路の同表記、サロゲートペア、制約付き EOS 到達不能。 |
| 辞書資産 | 既存の辞書バイナリからトークンを読み、生成された文法メタデータを決定的に比較。両 SHA が個別に照合されることを検査。分類辞書の合流後にも制約を適用。 |
| 活用・助詞 | 対応する全クラスの生成結果、同音異クラス、区間指定による活用形変換、助詞の肯定・否定・曖昧な複数候補。 |
| 既存の優先規則 | 「しろ」「しろい」「しろくろ」「しろあり」をコーパスに含め、`FindPathUnigramScopeTest` の「しろ + 医」を実行。 |
