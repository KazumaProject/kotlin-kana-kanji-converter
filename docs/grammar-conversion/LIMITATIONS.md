# 適用範囲

- 文法データは同じ辞書ビルドの `id.def` と資産が前提。生成時の件数照合と利用時のハッシュは組の不一致を検出する。生成者が同じ件数の別 `id.def` を渡す誤りを、既存バイナリだけから検出することはできない。実行時はロード済みの連接行列と POS ID 配列を照合する。
- 明示制約は指定した単語範囲と隣接文脈で成立する。意味、係り受け、格支配、分割をまたぐ任意の文法パターン、文法解釈の文全体にわたる選言には追加の文法状態や語彙データが必要。制約範囲に完全一致する辞書トークンが必要なので、1つのスパンで複数トークンの活用表現を指定する場合は、語幹と助動詞等それぞれに制約を設ける。
- 「以外な」の不存在は指定された辞書バイナリと明示制約で検証した。追加辞書が同一表記に正当な形容動詞語幹のラベルを付けた場合、辞書が提供する文法的な証拠に従う。表記を永久に除外する制約ではない。
- 活用生成の範囲は常用の5形式の規則。語彙固有の例外や文語、縮約、異体字の全形の生成に対応するには正式な語彙素・語幹・例外データを別に必要とする。助詞の判断は定義した局所規則に限り、後続文脈は連接費用に反映する。助詞候補の集合は呼び出し側が読みで指定する。
- 文脈規則による順位付けは既存の有限候補プールの規則を継承する。N-gram/Unigram で優先される全経路を全探索する API ではない。コスト同点の場合、制約付き Viterbi と A* は異なる合法経路を返し得る。
- 長い入力の辺数と一時メモリは語の候補密度、制約状態数、要求件数に依存する。トレースは調査時に明示して有効にする。
- 検証対象は本リポジトリの JVM と記録したローカル資産。Android/IME を対象とする挙動比較と特定リリースの出荷物試験は行っていない。
